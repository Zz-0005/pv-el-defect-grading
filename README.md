# pv-inspect · 光伏电池片 EL 缺陷分级

用 YOLOv8 分类头把一片光伏电池片的电致发光（EL）图像判成 **四级：良好 / 轻微 / 中度 / 严重**，
并给出处置建议与 Grad-CAM 缺陷定位。数据来自公开真实 EL 图像集 ELPV，全部指标可在本机一条命令复现。

```
真实 EL 图像 ──► 分级模型 ──► 级别 + 处置建议 ──► Grad-CAM 热力图
   (2624 张)      (YOLOv8n-cls)    判废/返修/降级/流转
```

---

## 1. 这个项目解决什么问题

EL 成像是光伏组件出厂前的标准检测手段：给电池片通电，让它自己发光，再拍近红外图像。
有隐裂、断栅、黑斑的电池片发光不均，在图上就是暗纹或黑块。

现场的做法是**人工看图分档**：熟练工一天要看上千张，疲劳后判级漂移；
而且"轻微"和"中度"的界限靠经验，同一片不同人可能给出不同档。

本项目要回答的不是"有没有缺陷"——那是二分类，一句话就完了；
而是**"有多严重，该判废还是降级"**。因为产线上的处置动作完全取决于档位：

| 级别 | 含义 | 处置动作 |
|---|---|---|
| G0 良好 | 缺陷概率 0.0 | 正常流转 |
| G1 轻微 | 缺陷概率 ≈ 1/3 | 降级使用 |
| G2 中度 | 缺陷概率 ≈ 2/3 | 返修复检 |
| G3 严重 | 缺陷概率 1.0 | 判废 |

## 2. 数据

**ELPV Dataset**（Buerhop-Lutz 等）——2624 张 300×300 8 位灰度 EL 图像，
来自 **44 块真实光伏组件**，每张带人工标注的缺陷概率与晶型（单晶 1074 / 多晶 1550）。

选择它的原因很实际：
- 它是**真实产线图像**，不是渲染合成；
- 标注的缺陷概率只有 4 个离散取值（0.0 / 1/3 / 2/3 / 1.0），
  所以"四级分级"是数据集本身的标注粒度，不是我为了凑任务切出来的；
- 体量小（93 MB），全部在本机可复现，不依赖外部服务器。

> 数据协议 CC-BY-NC-SA-4.0（非商业）。本项目仅用于教学与竞赛。

## 3. 关键设计：为什么不能随机切分

这是本项目最重要的一处工程判断。

2624 张图来自 44 块组件，**同一块组件上的相邻电池片成像条件几乎一致**。
如果按图片随机切分训练/测试，同一块组件的孪生样本会同时落在两边，
模型只要记住这块组件的底色就能答对，测试指标会虚高。

ELPV **没有提供组件 ID**。所以本项目的做法是：

1. 把每张图缩到 16×16 并做零均值单位方差归一化，作为"外观指纹"；
2. 用 k-means 聚成 44 组（对应数据集的 44 块组件），近似还原组件归属；
3. 用余弦相似度 ≥ 0.995 判定重复样本，把重复样本并进同一组（避免聚类的边界误差）；
4. **以组为单位**分配 train/val/test，组是原子的，绝不拆分；
5. 切分后再用两道检查验证：同组跨 split = 0，重复样本跨 split = 0。

实测结果：42 组，**零泄漏**。同一模型在随机切分下的测试准确率明显更高——
这组对照在 `results/` 里，是"为什么必须分组"的直接证据。

## 4. 为什么用 YOLOv8 分类头而不是检测头

ELPV 的标注是"整片电池的缺陷概率"，**没有缺陷实例的包围盒**。
硬套检测模型就要自己编框的真值，指标就变成自证的。

分级本身就是分类任务，用 YOLOv8 的 `-cls` 头是任务与模型匹配的做法。
缺陷的**位置**另用 Grad-CAM 从分类模型里反推——不需要额外标注，
而且顺带能检查模型有没有"看错地方"。

## 5. 快速开始

环境：Windows / Python 3.12 / 有 NVIDIA GPU 时自动启用（本机 RTX 3050 Ti 4 GB 足够）。

```bash
# 1) 建环境
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt

# 2) 下载并解包 ELPV（93 MB）
python scripts/fetch_data.py

# 3) 构建分级数据集 + 分组切分（含泄漏检查）
python -m pvinspect prepare

# 4) 训练三个对照实验
python -m pvinspect train --epochs 40

# 5) 在冻结测试集上评测
python -m pvinspect eval

# 6) 启动本地演示
python -m pvinspect serve
#   浏览器打开 http://127.0.0.1:8000
```

自检（不需要训练权重，几秒跑完）：

```bash
python -m pvinspect selftest
```

> 若 `python -m venv` 报 `ensurepip` 失败，可改用
> `python -m venv --without-pip --system-site-packages .venv`，
> 再用系统 pip 的 `--python` 指向 venv 安装。

## 6. 实验设计

| 实验 | 数据集 | 说明 |
|---|---|---|
| `E1_grouped` | ds4 | **四级分级 + 分组切分**（主方案） |
| `E1_random` | ds4_rand | 泄漏对照：四级分级 + 随机切分 |
| `E2_binary` | ds2 | 基线：二分类（合格/不合格）+ 分组切分 |
| `E3_three` | ds3 | 三档操作级：轻微+中度合并为"待复核" |

E1 的两组共用同一批样本、同一模型、同一超参，只有切分方式不同，
因此指标差异可以归因到"是否泄漏"。

另外做两项**决策层**处理（都不改模型权重）：

1. **训练集过采样**：四级样本量 911/215/73/408，中间两档严重不足。
   不过采样时模型会直接放弃这两类（实测 G1/G2 召回为 0）。
   只在 train 复制，val/test 不受影响。
2. **先验调整（logit adjustment）**：
   `p'(c|x) ∝ p(c|x) / π_c^τ`，把训练先验从输出概率里除掉，
   让决策边界往少数类偏。τ 只在**验证集**上按宏平均 F1 选，测试集只报告最终结果。

评测口径：
- 全部在**冻结测试集**上算，测试集从未参与训练或调参；
- 除 accuracy 外，单独报**宏平均 F1**（稀有级别 G2 只占 4%，会被 accuracy 掩盖）；
- 单独报**严重漏判率**：真实 G3 被判成 G0/G1 的比例，这是最不能出的错；
- 报**加权代价/千张**：按业务代价矩阵加权（G3→G0 记 20 分，G0→G3 记 2.5 分）。

## 7. 三个关键发现

### 7.1 随机切分会把指标抬高

同一模型，随机切分 vs 分组切分，准确率与宏 F1 都有可见差距。
这个差距**不是模型更强，而是泄漏**：同组件的孪生样本同时进了训练和测试。
具体差值见 `docs/实验记录.md` 第 2.1 节。

### 7.2 四级分级在跨组件泛化下，中间两档会坍塌

第一版模型（yolov8n，无过采样）在测试集上 G1、G2 的召回率都是 **0.000**——
它只会输出"良好"和"严重"两极。原因是长尾 + 跨组件域偏移：
模型学到的是"这块组件整体亮不亮"，而不是"缺陷有多严重"。

过采样 + 先验调整后中间档有所恢复，但仍是全任务里最弱的一环。
这个现象直接支撑了一个产品决策：**把分级粒度降到三档**（`E3_three`），
把"轻微/中度"合并为"待复核"——它们在产线上的处置动作本来就同属返修/降级。

### 7.3 Grad-CAM 的目标层不能取最后一层

最初把 CAM 挂在最后一层（7×7 特征图）上，热力图和缺陷位置几乎无关
（暗区/亮区响应比 ≈ 1.0，见 `scripts/layer_probe.py` 的实测）。
原因是深层特征图空间分辨率太低，上采样回原图后糊成一片。

改成"最深的、空间尺寸不小于输入 1/16 的特征图"（224 输入 → 14×14）后，
在真实严重缺陷样本上，热力图在暗区的强度是亮区的 **2.1~5.2 倍**；
在良好样本上则没有这种偏向。这是"热力图是否真的指向缺陷"的定量检验，
不依赖肉眼判断。

## 8. 结果

冻结测试集（582 张，分组切分，测试集从未参与训练或调参）：

| 实验 | 准确率 | 宏平均 F1 | 严重漏判率 | 加权代价/千张 |
|---|---|---|---|---|
| `E1_grouped` 四级 · 分组切分 | 0.7045 | 0.4371 | 0.2925 | 2715.6 |
| `E1_random` 四级 · 随机切分 | 0.7330 | 0.5538 | 0.2593 | 2005.0 |
| `E2_binary` 二分类 | 0.7182 | 0.7166 | — | 281.8 |
| **`E3_three` 三档（推荐）** | **0.7612** | 0.6211 | — | **238.8** |

三档模型 `E3_three` 的分类别表现：

| 档位 | 精确率 | 召回率 | F1 | 说明 |
|---|---|---|---|---|
| 合格 | 0.725 | **0.936** | 0.817 | 良品几乎不会被误拦 |
| 待复核 | 0.444 | 0.211 | 0.286 | **最弱的一档**，两档合并的代价 |
| 判废 | **0.914** | 0.651 | 0.760 | 判废的误伤率很低 |

两点读法：

- **代价从 2715.6 降到 238.8**：四级模型把"严重"判成"良好"的代价极高（每次记 20 分），
  三档模型基本消除了这种错误。这是"分级粒度"决策的直接收益。
- **待复核召回只有 0.211**：这是诚实的数据——把轻微和中度合并后，
  这一档本身就是最难的两类之和。它在产线上的意义是"推给人看一眼"，
  漏掉这些会退化成二分类，但不会造成判废错误。

完整指标、混淆矩阵、τ 扫描见 [`docs/实验记录.md`](docs/实验记录.md)
（由 `scripts/make_report.py` 从 `artifacts/results/results.json` 自动生成），
图表与错例图在 `artifacts/results/`。

## 9. 已知局限（答辩时主动交代）

1. **分级标准来自数据集标注，不是行业标准**。ELPV 的 4 档概率是标注者给的，
   真实产线的判废标准（按 IEC 61215 等）更细。
2. **组件分组是近似的**。k-means 44 组只是尽量还原组件归属，
   真实组件 ID 不在数据集里，泄漏检查是"尽力而为"而非严格保证。
3. **没有缺陷类型**。ELPV 不标注隐裂/断栅/黑斑，只有整体严重度。
4. **单晶/多晶混合训练**，没有按晶型分别建模。
5. **G2 样本只有 106 张**，测试集仅 17 张，该级别指标置信区间很宽。
6. **跨组件泛化是真正的瓶颈**：训练损失降到 0.18，验证损失却升到 1.34，
   模型在记训练组件。这是数据规模（44 块组件）决定的，不是调参能解决的。

## 10. 目录结构

```
pv-inspect/
├── src/pvinspect/
│   ├── config.py     分级定义、代价矩阵、超参、过采样倍数
│   ├── prepare.py    标签转换、k-means 分组、切分、过采样、泄漏检查
│   ├── train.py      四组对照实验
│   ├── evaluate.py   混淆矩阵、分级指标、代价分析、先验调整、出图
│   ├── cam.py        Grad-CAM 定位（含目标层选择规则）
│   ├── serve.py      本地演示服务（仅标准库 http.server）
│   ├── compat.py     受限环境适配（串行校验、缓存目录、临时目录）
│   └── selftest.py   21 项自检
├── scripts/
│   ├── fetch_data.py           下载 ELPV
│   ├── resumable_download.py   分块续传下载器
│   ├── analyze_data.py         数据分布摸底
│   ├── make_report.py          结果 → docs/实验记录.md
│   ├── layer_probe.py          CAM 目标层选择实验
│   ├── mvs_capture.py          接海康 MVS 相机采图（可选）
│   └── pipx.py                 受限环境下的 pip 启动器
├── artifacts/        数据集、模型、结果（不进版本库）
└── docs/             实验记录、局限与边界
```
