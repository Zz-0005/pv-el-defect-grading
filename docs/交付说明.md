## 一、跑起来（复制粘贴即可）

**现场演示只要双击一个文件：**

```
双击  pv-inspect\启动演示.bat
```

浏览器会自动打开页面，把 `demo\样本` 里的图拖进去就行。关掉黑窗口即停止。

命令行方式（等价）：

```bash
cd F:\展示作品\pv-inspect

# 演示
.venv\Scripts\python -m pvinspect serve

# 自检（不训练，10 秒，用来证明代码没坏）
.venv\Scripts\python -m pvinspect selftest
```

**上台前必看**：[`docs/演示脚本.md`](演示脚本.md) —— 逐句台词、60 秒流程、翻车预案。

如果要重新训练（约 20 分钟/组，需要 GPU）：

```bash
.venv\Scripts\python -m pvinspect prepare           # 重建数据集（含泄漏检查）
.venv\Scripts\python -m pvinspect train --epochs 50 # 训练四组
.venv\Scripts\python -m pvinspect eval              # 出全部指标与图
.venv\Scripts\python scripts\make_report.py         # 生成 docs/实验记录.md
.venv\Scripts\python scripts\make_demo_assets.py    # 生成演示样本与拼图
```

## 二、四个模型分别是什么

| 权重 | 任务 | 说明 | 建议 |
|---|---|---|---|
| `E3_three.pt` | 三档：合格 / 待复核 / 判废 | **推荐作为主方案** | 演示默认用它 |
| `E1_grouped.pt` | 四级：良好/轻微/中度/严重 | 主实验，暴露了中间档坍塌问题 | 讲"我试过更细的分级" |
| `E1_random.pt` | 四级，随机切分 | 泄漏对照 | 讲"为什么必须分组切分" |
| `E2_binary.pt` | 二分类：合格/不合格 | 基线 | 讲"二分类不够用" |

## 三、答辩时的叙事顺序（对应四维评分）

**创新（40 分）** — 不要只说"我用了 YOLO"。说这三件事：

1. **任务定义**：不是"检测有没有缺陷"，是"缺陷有多严重、该判废还是返修"。
2. **切分设计**：ELPV 没有组件 ID，我用外观聚类还原 44 块组件，按组切分，
   并做了两道泄漏检查（同组跨 split = 0，重复样本跨 split = 0）。
3. **负结果也是结果**：四级分级的中间两档在跨组件泛化下坍塌（召回 0.00），
   我做了过采样和先验调整，验证集显示先验调整无效（τ=0 最优），
   于是把粒度降到三档——**这是数据支撑的决定，不是妥协**。

**价值（30 分）** — 说清楚三档对应什么动作：合格正常流转、待复核返修/降级、判废淘汰。
再加一句代价：加权代价从四级模型的上千降到 238.8 / 千张。

**实现（20 分）** — 现场跑 `serve`，拖一张图，1.4 秒出结果和热力图。
如果卡住，直接说"代码在这里，`selftest` 23 项全过，你现在可以在我机器上跑"。

**协作（10 分）** — GitHub 链接 + 这篇 README；数据集引用写清楚。

## 四、必须诚实说明的四件事

评委会问，主动说比被问出来强：

1. **分级档位来自 ELPV 标注，不是 IEC 判废标准**；
2. **组件分组是近似的**（k-means 44 组），不能保证零泄漏，只能说"做了比随机切分严格得多的防护"；
3. **没有缺陷类型**（隐裂/断栅/黑斑），ELPV 不提供；
4. **跨组件泛化是真正的瓶颈**：训练损失 0.18、验证损失 1.34，模型在记训练组件，
   这是 44 块组件的数据规模决定的。

## 六、如果要换成自己的数据

把 `data/elpv/...` 换成你的图 + 一个 `labels.csv`（两列：文件名, 缺陷概率），
其余流程不用改。分级档位在 `src/pvinspect/config.py` 的 `GRADES` /
`GRADES3` / `GRADE3_OF` 里改。
